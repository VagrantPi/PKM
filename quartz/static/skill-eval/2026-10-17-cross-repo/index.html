跨 repo：工具自動連上的是 0 條，grep 一樣全對

TypeScript backend 透過 HTTP（42 個呼叫點、41 個端點）和 gRPC（1 條）呼叫一個 Go 服務。三個程式碼圖譜工具都沒能自動接上任何一條跨 repo 呼叫。4 題跨 repo 實戰題，只用 grep 的 agent 和有工具的 agent 一樣全對，而且這次最便宜（N=1，token 差 6–33%）。同時，獨立的再驗證推翻了上一份四方報告的「精確度都滿分」。

跨 repo 自動連結 · 對照真值

真值：backend 打 Go 服務的 42 個 HTTP 呼叫點（每個都對到路由行和 handler），加上 1 條 gRPC。全部用 grep 驗證過。

工具HTTP（42）gRPC（1）為什麼
GitNexus group（自動）00抽出 183 個合約、只配對到 1 條，而且是錯連（Go 服務自己的 e2e test 連到 backend 的 proto 副本）。Go 端的 extractor 只認 x.GET()／http.HandleFunc()，認不得 Go 1.22 的 mux.Handle("POST /path")，Go 服務的 Route 節點數是 0。TS 端要求 axios receiver 是單一識別字，this.client.post() 不算。gRPC client 是執行期 protoLoader 載入，偵測不到。
GitNexus＋手寫 manifest清單 41/41，但掛到符號 01（部分）HTTP 沒有 Route 節點可掛，manifest 只是一份清單，impact 用不上。gRPC 解到產生出來的 Unimplemented…Server.Chat stub；從 stub 往上游跑 impact 能跨 repo，從真正的 handler 跑還是 0。
graphify merge-graphs00兩張圖之間沒有任何直接相連的邊；.proto 不解析；path 用名稱查詢會撞到 4 個同名節點。

團隊導入前要知道的事

  • 授權：GitNexus 是 PolyForm Noncommercial，公司使用要另外買授權；另外三個是 MIT 或 Apache-2.0。
  • 會寫進開發機的東西：
    • codegraph：MCP 設定、auto-allow 規則、UserPromptSubmit hook。
    • GitNexus：analyze 預設會寫 skills、hooks、AGENTS.md（加 --index-only 可關）。
    • graphify：PreToolUse hook。
    • UA：兩個 hook，會叫 agent「不用問使用者」直接重分析。
  • 網路：
    • codegraph：匿名使用統計預設開（含 machine id、版本、OS、agent 名稱、各工具每日次數等，不含程式碼與路徑；可用 DO_NOT_TRACK=1 關），跟它 README 寫的「No external services」不一致。
    • GitNexus：每 24 小時檢查一次 npm 更新。
    • graphify：處理文件時會自動挑環境裡找到的 LLM key。
  • 共享索引：
    • GitNexus：有 mcp --http（綁 localhost 以外的位址才強制要 token；serve 本身沒有驗證）、Docker、auto-sync。
    • graphify、UA：可以把圖 commit 進 repo。
    • codegraph：只能每人在本機建，SQLite 跟作業系統綁定。
  • 版本與文件不同步：GitNexus 的 README 是 main 分支（--skip-embeddings 在 1.6.12 會直接報 unknown option）；graphify 8 天出了 10 版；UA 2.9.7 沒有對應的 tag。
  • 跨 repo 實際可行的做法：用腳本從兩邊的程式碼產生一份機器可讀的合約表（呼叫點 → 路由 → handler），在 CI 檢查，再讓 agent 先查表。proto 收斂成單一來源：這次兩份副本已經只差在註解上不同步。

條件與限制

  • 只測了一組 repo（TS ↔ Go，41 個端點，命名非常規律），對 grep 特別有利。換成動態組 URL、命名不規律或端點多很多的系統，結論可能不同。
  • N=1：4 題每組只答一次；評分由主線依真值表自評。真值表在實驗中修正過一次（補上 2 個漏列的呼叫者）。
  • 版本：GitNexus 1.6.12（--index-only，沒有 embedding，全文搜尋沒裝起來，MCP 工具沒測）、graphify 0.9.92（--code-only）、codegraph CLI 1.4.1（1.6.2 在再驗證中跑過 TS 全量和 TS／Go 小型重現；跨 repo 和 Go route → handler 沒有在 1.6.2 上重跑）。
  • 由 7 個 subagent 分工：再驗證、文件研究、跨 repo 機制實驗、4 個實戰題分組。最後由獨立的對抗式驗證逐條核對，挑出 12 處不精確，已全部修正。
