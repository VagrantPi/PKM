怎麼選

repo 內導航
codegraph 1.6.2：召回率和精確度都最好。常見方法名的 caller 只當候選，要用 grep 篩。Go 的 route → handler 不要信它，直接讀 router。
跨 repo
不靠工具。用腳本從兩邊程式碼產生一份「呼叫點 → 路由 → handler」的合約表，在 CI 雙向檢查，SSE 事件名稱也一起比對；再讓 agent 先查表。
codebase-memory
等它支援 Go 1.22 路由和純字串 URL，再用簽章過的 release 重評。
GitNexus／graphify
GitNexus 授權非商用，TS 召回率低；graphify 只有文件也要進圖時才考慮。

條件與限制

  • 只測一組 repo：命名規律、URL 多寫成字面值，對 grep 有利。換成動態組 URL 或端點更多的系統，結論可能不同。
  • N=1：5 題每組只答一次，由主線依真值自評。真值在實驗中修正過兩次。
  • 版本：
    • codebase-memory：7 月 5 日的 dev build，最新 release 沒測。
    • codegraph：1.4.1；1.6.2 只測過 repo 內的 TS 和小型重現。
    • GitNexus：1.6.12，--index-only，沒有 embedding 和 MCP 工具。
    • graphify：0.9.92，--code-only。
  • codebase-memory 組作答時，同一個 store 正在跑 cross-repo pass：那組回報「沒有 CROSS 邊」，應該是在 pass 之前查的。pass 產生的連結全錯，不影響結論。
