踩到的坑 · 範圍設成子目錄會悄悄漏掉別名 import

第一輪我直接對 backend/src/services 跑，tsconfig.json 不在範圍內，@/ 路徑別名就解析不了。services 裡 997 個 import 用別名、只有 250 個是相對路徑，結果 import 邊只建出 128 條。file-analyzer 又被規定「只能依 import 資料建 calls 邊」，quotaService 這類跨檔呼叫就這樣被丟掉了。工具沒報錯，只有一個 agent 在回報裡提到。

改成專案根設為 backend/，用 exclude 只留 src/services/** 和 tsconfig 之後，import 邊回到 278 條。第一輪跑了 11 批、約 89 萬 token，全部作廢。

用法：UA 的範圍要包含 tsconfig（或其他路徑別名設定），縮小範圍用 --exclude，不要直接把子目錄當專案根。

條件與限制

  • N=1：只有 voice-call 那一批重跑過一次（N=2），其他都只跑一次，不做統計顯著性宣稱。
  • 範圍只有 services/（232 個 TS 檔）。controllers、worker、tests 都不在範圍內，任何「範圍外的 caller」兩邊都看不到。
  • 顆粒度不同：codegraph 是方法層級，UA 是 class 層級，第 ② 維本質上是在拿 UA 回答它設計上不擅長的問題。
  • UA 管線是我手動編排的：照 /understand 2.9.7 的 SKILL.md 逐階段派 agent，但有三處偏離。
    • 批次參數放在檔案裡傳，沒有直接寫進 prompt。
    • 第二輪的 scan 步驟用它附的腳本直接組出來，沒有派 project-scanner agent。
    • 跳過 Phase 7 的 fingerprint。
    跟一鍵跑 /understand 的結果可能有差。
