## 🎯 什麼情境該想到我

當你「想測一個方法，但它裡面夾了一段在測試環境下根本跑不起來、或你根本不關心的行為」的時候。

這是全書解依賴技術的核心：「子類化並重寫方法是物件導向程式中解依賴的核心技術。實際上本章所講的許多其他的解依賴手法都是該手法的變種。」（p.314）

核心理念只有一句：「你可以在測試環境下利用繼承來將並不關心的行為架空，或存取到你所關心的行為。」（p.314）——也就是同時服務**分離**（把礙事的依賴切掉）與**感知**（讓你看得到內部發生了什麼）兩個目的。

書中的例子：`MessageForwarder` 有個私有方法 `createForwardMessage`，測試時不想依賴 `MimeMessage` 類別，「因為 `MimeMessage` 用到了一個叫做 session（會話）的變數，而在測試的時候是沒法建構出一個真正的 session 出來的」（p.315）。解法是把 `createForwardMessage` 設為受保護的，然後在一個測試用子類別中重寫它。

代價有多小？「在產品程式碼中，我們實例化的是 `MessageForwarder`；而在測試程式碼中，實例化的則是 `TestingMessageForwarder`。你看，我們以最少的修改換來了所需要的分離。實際上只不過是將 `createForwardMessage` 的存取權限從私有換成了受保護的。」（p.315）

## ⚙️ 怎麼用（步驟）

書中列出的步驟（p.316–317）：

1. **找出你想要分離出來的依賴，或者想要進行感知的地點。找出盡量少的一組方法來完成你的目標。**
2. **確定了重寫哪些方法之後，還得確保它們都是可重寫的。** 這一步根據語言的不同有所不同：C++ 中首先要將它們設為虛擬函式；Java 中它們必須是非 final 方法；而在許多 .NET 語言中，你還得明確地將這些方法設為可重寫的。
3. **在某些語言中，你需要調整這些方法的存取權限才能在子類別中重寫它們。** 比如在 Java 和 C# 中，必須至少是受保護的方法才能被子類別中的方法重寫；而在 C++ 中私有虛擬函式仍然是可以在子類別中重寫的。
4. **建立一個子類別並在其中重寫這些方法。確保你的確能夠在測試用例中建構該類別。**

### 「疊紙視圖」——怎麼找出該重寫哪個方法

Feathers 描述了他自己在腦中用的一個視覺化技巧（p.316）：

> 「我看著一個方法，然後在腦海裡設想所有可用於將其語句和表達式分組的方式。對於一個方法中我可以確定出來的幾乎任何細小的程式碼片段，我猜想能否將其提取到一個方法中，進而在測試中將其替換為另一個方法。這就好像我將一層半透明的紙放在程式碼之上，在這層半透明的紙上我可以放置用於替換目標程式碼片段的程式碼。這疊紙就是我的測試物件，而從上往下看到的方法便是會在測試中被執行到的方法。」

書中的圖 25-6 標題就是「`TestingAccount` 浮於 `Account` 之上」（p.316）。

但他馬上補了一句重要的紀律：「疊紙視圖法能夠幫助我看到什麼是可能的，但當我真正開始使用子類化並重寫方法手法時，仍然還是盡量去重寫**既有的**方法。畢竟我們的目的是將測試安置到位，而在沒有測試的情況下提取方法常常是危險的。」（p.316）——想像可以很自由，實際下手要保守。

## ⚠️ 注意 / 什麼時候不適用

- **難易程度取決於原本的功能分解好不好。** 「通常，一個類別當中的功能分解的好壞決定了你使用該手法來分離依賴時的難易程度。好的情況下，你想要分離出的依賴會被隔離在一個小小的方法當中。而在糟糕的情況下，你可能就需要重寫一個較大的方法才能分離出依賴了。」（p.315）方法越大，你架空掉的東西就越多，風險就越高。
- **它很強，所以要小心用。** 「子類化並重寫方法是個強大的手段，但用的時候也需小心。」（p.316）書中拿自己的例子檢討：「比如在前面的例子中我可以返回一個沒有主題、寄件人地址等資訊的空消息物件，但這麼做是有特定前提的——比如我正在測試的是能否將一個消息從系統中的一個地方傳到另一個地方，而並不關心消息的具體內容和地址，這時候這麼做才是安全的。」（p.316）**架空掉的東西必須真的是這個測試不關心的東西**，否則你測到的是假象。
- **你會為了測試放寬封裝。** 書中的做法就是把私有方法改成受保護的（p.315）。這確實讓設計「暫時變差」——一個原本封裝良好的實作細節，因為測試而被打開成可被繼承覆寫的擴充點。Feathers 的立場是：這是換取測試安置到位的最小代價，而且它確實是**代價**，不是免費的。
- **語言差異會咬你。** 步驟 2、3 列的差異不是註腳：C++ 要虛擬函式、Java 要非 final、.NET 多半要明確標記可重寫；存取權限規則 Java/C# 與 C++ 又不同（p.316–317）。
- **建構函式裡的行為它救不了。** 在不支援建構函式中呼叫虛擬函式的語言（如 C++）裡，光子類化並重寫方法是無效的——書中在替換實例變數一節專門示範了這個陷阱（p.317–318）。
- **別為了用它而先做方法提取。** 沒有測試保護時提取方法本身就是危險動作（p.316）。
