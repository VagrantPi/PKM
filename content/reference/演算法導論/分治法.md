## 🎯 什麼情境該想到我
當你「**一個大問題可以拆成幾個「同樣形狀」的小問題**」的時候。
★ 它是一個**設計範式**（不是某個演算法），而它最實用的產物是**主定理**——一個能秒算遞迴複雜度的工具。

## ⚙️ 怎麼用（三步與主定理）

### 三步

| 步驟 | 做什麼 |
|---|---|
| **Divide** | 把問題拆成若干個同型的子問題 |
| **Conquer** | 遞迴解決子問題（小到一定程度就直接解） |
| **Combine** | 把子問題的解合併成原問題的解 |

**★ 不同演算法的「重量」落在不同步驟**——這是理解它們差異的關鍵：

| 演算法 | Divide | Combine |
|---|---|---|
| **[[合併排序]]** | 輕（取中點 $O(1)$） | **重**（合併 $O(n)$） |
| **[[快速排序]]** | **重**（分割 $O(n)$） | 輕（免費） |
| **[[二分搜尋]]** | 輕 | 免費（只遞迴一邊） |

### ★ 主定理（Master Theorem）

對形如
$$T(n) = a\,T\!\left(\frac{n}{b}\right) + f(n), \qquad a \ge 1,\; b > 1$$

令 $\displaystyle n^{\log_b a}$ 為「**遞迴的葉子總工作量**」，與 $f(n)$（**每層合併的工作量**）比大小：

| Case | 條件 | 結果 | 誰主導 |
|---|---|---|---|
| **1** | $f(n) = O\!\left(n^{\log_b a - \varepsilon}\right)$ | $T(n) = \Theta\!\left(n^{\log_b a}\right)$ | **葉子**（遞迴底層） |
| **2** | $f(n) = \Theta\!\left(n^{\log_b a}\right)$ | $T(n) = \Theta\!\left(n^{\log_b a}\log n\right)$ | **每層一樣重** |
| **3** | $f(n) = \Omega\!\left(n^{\log_b a + \varepsilon}\right)$ ＋ 正則條件 $a f(n/b) \le c\,f(n)$ | $T(n) = \Theta(f(n))$ | **根**（最上層的合併） |

**直覺**：畫出遞迴樹，比較「**最上面那一層的合併成本**」與「**最底層所有葉子的成本**」，誰大誰主導；一樣大就多一個 $\log n$。

### 套用範例

| 遞迴式 | $a$ | $b$ | $n^{\log_b a}$ | $f(n)$ | Case | 結果 |
|---|---|---|---|---|---|---|
| **[[合併排序]]** $2T(n/2)+\Theta(n)$ | 2 | 2 | $n$ | $\Theta(n)$ | **2** | $\Theta(n\log n)$ |
| **[[二分搜尋]]** $T(n/2)+\Theta(1)$ | 1 | 2 | $n^0 = 1$ | $\Theta(1)$ | **2** | $\Theta(\log n)$ |
| **二元樹走訪** $2T(n/2)+\Theta(1)$ | 2 | 2 | $n$ | $\Theta(1)$ | **1** | $\Theta(n)$ |
| **Karatsuba 乘法** $3T(n/2)+\Theta(n)$ | 3 | 2 | $n^{1.585}$ | $\Theta(n)$ | **1** | $\Theta(n^{1.585})$ |
| **Strassen 矩陣乘** $7T(n/2)+\Theta(n^2)$ | 7 | 2 | $n^{2.807}$ | $\Theta(n^2)$ | **1** | $\Theta(n^{2.807})$ |
| 某些切割問題 $2T(n/2)+\Theta(n^2)$ | 2 | 2 | $n$ | $\Theta(n^2)$ | **3** | $\Theta(n^2)$ |

> ★ **Karatsuba 與 Strassen 是分治最漂亮的成果**：
> 它們的價值不在「把問題拆小」（那誰都會），而在**用更多的加減法換掉一次乘法／矩陣乘**，
> 把 $a$ 從 4 降到 3、從 8 降到 7 —— **$a$ 少一，指數就降下來。**
> **分治的威力來自「減少子問題的數量」，不是「拆得更細」。**

### ★ 主定理不適用時
- $f(n)$ 落在兩個 case 之間的「縫隙」（例如 $T(n) = 2T(n/2) + n\log n$）
- 子問題大小不等（$T(n) = T(n/3) + T(2n/3) + n$）
- → 改用**遞迴樹**或**代入法**證明

### ★ 分治 vs 動態規劃（最重要的界線）

| | **分治** | **[[動態規劃]]** |
|---|---|---|
| 子問題 | **互相獨立、不重疊** | **★ 重疊**（同一個子問題被算很多次） |
| 做法 | 直接遞迴 | **記憶化 or 自底向上表格** |
| 例子 | 合併排序、快排、二分搜尋 | 費氏數列、背包、最長公共子序列 |

```
費氏數列用純分治：
fib(5) → fib(4) + fib(3)
         fib(3)+fib(2)  fib(2)+fib(1)
         ★ fib(3) 被算了兩次，fib(2) 三次⋯ → O(φⁿ) 指數爆炸

加上記憶化 → O(n)
```

> ★ **判準：畫出遞迴樹，看有沒有重複的節點。**
> **有重複 → 用 DP；沒重複 → 分治就夠了。**

### 還有一個實務價值：**平行化**
子問題獨立 → **可以並行**。
```go
func parallelMergeSort(a []int, depth int) {
    if len(a) < 1000 || depth <= 0 {   // ★ 太小就別開 goroutine，開銷大於收益
        sequentialSort(a)
        return
    }
    mid := len(a) / 2
    var wg sync.WaitGroup
    wg.Add(1)
    go func() { defer wg.Done(); parallelMergeSort(a[:mid], depth-1) }()
    parallelMergeSort(a[mid:], depth-1)   // ★ 當前 goroutine 做另一半，不要開兩個
    wg.Wait()
    merge(a, mid)
}
```
★ **限制遞迴深度**，否則會開出成千上萬個 goroutine——**排程開銷會遠大於平行的收益**。

## ⚠️ 注意 / 什麼時候不適用

- **★ 子問題重疊就不要用分治**，會指數爆炸 → 改 [[動態規劃]]。
- **遞迴有開銷**。小問題要切換成迭代或簡單演算法（所有排序在小分段切 [[插入排序]] 就是這個道理）。
- **堆疊深度**。不平衡的分治（如退化的快排）會爆堆疊。
- **主定理不是萬用**，有縫隙情況。
- **平行化要限制深度**，否則 goroutine/thread 的開銷吃掉收益。
- **分治不保證更快**。$a$、$b$、$f(n)$ 的組合可能讓它比直接做還慢——**先算主定理再實作。**
