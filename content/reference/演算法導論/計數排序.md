## 🎯 什麼情境該想到我
當你「**要排的是整數，而且值域不大**」的時候——年齡、分數、狀態碼、月份、評分。
★ 它是**線性時間**的，而理解「它憑什麼突破 $\Omega(n\log n)$」比記住它本身更重要。

## ⚙️ 怎麼用（機制與推導）

### ★ 先搞懂：$\Omega(n\log n)$ 的下界是怎麼來的

**比較排序**（只靠「$a < b$ 嗎」來決定順序）可以畫成一棵**決策樹**：
- 每個內部節點是一次比較，兩個分支是「是／否」
- 每個**葉節點**是一種可能的輸出排列

$n$ 個元素有 $n!$ 種排列 → **樹至少要有 $n!$ 個葉節點** → 高度（最差比較次數）至少 $\log_2(n!)$。

由 Stirling 近似 $\log_2(n!) = \Theta(n\log n)$：

$$\boxed{\text{任何比較排序的最差情況至少需要 } \Omega(n\log n) \text{ 次比較}}$$

> ★ **關鍵字是「比較」。**
> 這個下界的**前提**是「你只能透過比較獲得資訊」。
> **計數排序不做比較——它直接把「值」當成「陣列索引」用。**
> 它不是打破了數學定理，而是**根本不在定理的適用範圍內**。

### 運作機制

```
輸入 a = [2, 5, 3, 0, 2, 3, 0, 3]，值域 k = 6（0..5）

① 統計每個值出現幾次
   count = [2, 0, 2, 3, 0, 1]
            0  1  2  3  4  5

② ★ 改成「前綴和」：count[v] = 有幾個元素 ≤ v
   count = [2, 2, 4, 7, 7, 8]
                       ↑ 值為 3 的元素，最後一個該放在索引 6（=7-1）

③ ★ 從後往前掃輸入，放進輸出陣列
   （從後往前是「穩定」的關鍵）
```

```go
// a 的元素都在 [0, k)
func CountingSort(a []int, k int) []int {
    count := make([]int, k)
    for _, v := range a {
        count[v]++
    }
    // 前綴和：count[v] = 有幾個元素 <= v
    for v := 1; v < k; v++ {
        count[v] += count[v-1]
    }
    out := make([]int, len(a))
    // ★ 一定要從後往前，否則不穩定
    for i := len(a) - 1; i >= 0; i-- {
        count[a[i]]--
        out[count[a[i]]] = a[i]
    }
    return out
}
```

### ★ 「從後往前」為什麼是穩定性的關鍵

`count[v]` 記錄的是「值為 $v$ 的元素該放的**最後一個位置**」。
**從後往前掃**，輸入中**較後面**的元素先被放進**較後面**的位置 → 相對順序保持不變。

如果從前往後掃，先掃到的元素會被放進後面的位置 → **相等元素的順序被反轉**。

> ★ **這不是細節，是 [[基數排序]] 能運作的唯一前提。**
> 基數排序靠「先排低位、再排高位」，而高位排序時**必須保住低位已經排好的順序**——
> 沒有穩定性，基數排序完全是錯的。

### 複雜度

| | |
|---|---|
| **時間** | $\Theta(n + k)$ |
| **空間** | $\Theta(n + k)$ |
| **穩定** | ✅（靠從後往前） |
| **原地** | ❌ |

**★ 什麼時候真的是「線性」**：只有當 $k = O(n)$ 時，$\Theta(n+k) = \Theta(n)$。
$k = 10^9$（排 32 位元整數）而 $n = 1000$ 時，它比任何比較排序都慢得多——**而且會配置 4 GB 記憶體**。

## ⚠️ 注意 / 什麼時候不適用

- **★ 值域 $k$ 決定一切**。$k \gg n$ 時完全不能用。使用前先算 `max - min`。
- **值域可以平移**。值在 `[100000, 100100]` 時，開 `k = 101` 的陣列並減去 `min` 即可——**不要開 100101 大小的陣列**。
- **只能排「能當索引」的東西**：非負整數（或可映射成整數的：列舉、字元、日期序號）。**浮點數、任意字串不行。**
- **負數要先平移**。
- **一定要從後往前掃**，否則穩定性沒了，`基數排序` 會跟著壞掉。
- **實務上很少單獨使用**。真正的價值是**當 [[基數排序]] 的內層**，以及桶排序類的前置步驟。
- **值域很大但分布集中時**，考慮桶排序（bucket sort）而非計數排序。
